## 2. Цели и границы

### Цели

- Одностраничный лендинг на русском для Никиты: фриланс-разработчик и автор проектов.
- Максимально близкая к референсу композиция, сетка, типографика, отступы, цвета, тени, карточки и характер анимаций.

- Портфолио как система: новые работы добавляются только в JSON + файл превью, без правки вёрстки.
- Docker Compose для продакшна и разработки, README и инструкции для GitHub Desktop.
- SEO, доступность, `prefers-reduced-motion`, Lighthouse 90+.

### Не входит

- CMS, админка, база данных, формы с бэкендом.
- Реальные ссылки Telegram/VK (пока неизвестны) и реальные кейсы (пока нет).
- Отдельные страницы кейсов, блог, мультиязычность, аналитика, оплата.
- Копирование ассетов и текстов референса.

### 3.3. Типографика

- Референс — геометрический гротеск с одинарной «g», плотным трекингом и крупными кеглями. Ближе всего Satoshi/General Sans, но у них нет надёжной кириллицы.
- Выбираем **Manrope Variable** (OFL, кириллица + латиница, вариативные веса). Он сохраняет геометрию, округлые окончания и хорошо работает в крупных заголовках.
- Подключение: `@fontsource-variable/manrope`, self-host, `woff2`, `font-display: swap`, preload кириллического сабсета.
- Фолбэк: `Inter, system-ui, -apple-system, "Segoe UI", sans-serif`.
- Заголовки: 500–600, tracking отрицательный. Body: 400–500, серый.
- Все тексты русские, короткие; латиница — только технологии и бренды.

### 3.4. Что переносим, а что адаптируем

**Переносим:**

- Чёрный кинематографичный hero, центральную композицию, белую pill-кнопку, светящийся стеклянный знак, луч, зерно, парящие точки.
- Крупные центрированные заголовки секций с pill-бейджем и серым подзаголовком.
- Тонкие рамки, 20 px радиусы, внутренний highlight, мягкое белое свечение, отсутствие цветных акцентов.
- 4 высокие карточки с уникальными визуалами (услуги).
- 3 горизонтальные карточки (процесс).
- Bento-сетку с разными span (почему я).
- Монохромные иконки, grayscale-логотипы технологий, бесконечную ленту.
- Медленные, сдержанные анимации.

**Адаптируем:**

- Текст и брендинг — свои (Никита, услуги, процесс).
- Вместо чужого 3D-рендера — собственный анимированный WebGL silk-шейдер + CSS-свет/параллакс.
- Вместо логотипов клиентов — стек технологий.
- Вместо «How it Works» — услуги; вместо «Introduction» — процесс.
- Портфолио — карточки с реальными превью 4:3, а не абстрактные промо-карточки.
- Нижняя часть (контакты, футер) проектируется в том же стиле, так как в референсе обрезана.

### 3.5. Живой hero и 21st.dev

Пользователь выбрал анимированный фон. На 21st.dev найдены подходящие WebGL-компоненты:

- **Silk shader** — MrKyzen: https://21st.dev/community/shaders/silk-shader-981104ba-e0ea-42dd-a80c-66b6ca6d41cd
- **Silky Moving Background** — Adam Guerreiro: https://21st.dev/community/shaders/silky-moving-background-81f294a4-f959-4326-9a72-f00dada6663f
- **Fintech Waves** — M C George: https://21st.dev/community/shaders/fintech-waves-4d5d975f-e4a6-43d7-a808-c69cc7034a77

Код этих компонентов на 21st.dev закрыт («Unlock the shader code»), поэтому 1:1 не копируется. Берём характер: монохромные шелковые волны, медленное течение, доменный warp, мягкий свет, реакция на курсор. Пишем **собственный компактный GLSL-шейдер**:

- один fullscreen quad на WebGL2, без Three.js и R3F;
- uniforms: `u_time`, `u_resolution`, `u_pointer`, `u_dpr`;
- палитра только чёрный/белый/серый;
- центральный луч и виньетка — CSS поверх canvas;
- fallback: статичный WebP-кадр + CSS-градиент, если WebGL недоступен;
- отключение при `prefers-reduced-motion`, пауза при уходе со вкладки и вне вьюпорта;
- DPR ≤1.5 на десктопе, ≤1 на мобиле; 30 fps на мобиле, 60 fps на десктопе;
- canvas `aria-hidden="true"`, `pointer-events: none`.

Это даёт живую сцену без ~150 КБ Three.js и без риска, что красивый фон «съест» Lighthouse.

## 4. Стек и ключевые решения

| Слой        | Решение                                           | Почему                                                                                                                                                 |
| ----------- | ------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Каркас      | **Astro 7** (static)                              | Контентный лендинг, минимум JS, отличный Lighthouse, простая раздача статики через nginx                                                               |
| Интерактив  | **React 19** islands                              | Header с мобильным меню, портфолио с фильтром, кнопки контактов                                                                                        |
| Язык        | TypeScript strict                                 | Типы для данных портфолио и компонентов                                                                                                                |
| Стили       | **Tailwind CSS v4** + `@tailwindcss/vite`         | CSS-first токены через `@theme`, без `tailwind.config.js`                                                                                              |
| UI-кит      | **shadcn/ui** (Astro-пресет)                      | Button, Badge, Card, Sheet, ToggleGroup; доступные примитивы Radix                                                                                     |
| Паттерны    | **21st.dev**                                      | Silk shader / Silky Moving Background (hero), Spotlight Card, Infinite Marquee, Bento Grid, Shiny Button; берём идею и пишем свой код, не копируем 1:1 |
| Hero-фон    | **Raw WebGL2 + GLSL**                             | Один fullscreen quad, без Three.js/R3F; живая монохромная сцена при малом весе                                                                         |
| Анимации    | **Motion 14** (`motion/react` + vanilla `motion`) | Reveal, layout-анимации фильтра, hover; уважает reduced motion                                                                                         |
| Скролл      | **Lenis 1.3**                                     | Плавный скролл и якоря; отключается при reduced motion                                                                                                 |
| Иконки      | **Lucide** (`@lucide/astro`, `lucide-react`)      | Единый набор, ISC                                                                                                                                      |
| Бренды      | **Simple Icons**                                  | CC0, grayscale-логотипы технологий                                                                                                                     |
| Шрифт       | **Manrope Variable**                              | OFL, кириллица, близкая геометрия                                                                                                                      |
| Валидация   | **Zod**                                           | Проверка `projects.json` на этапе сборки                                                                                                               |
| Изображения | **sharp**                                         | Скрипт конвертации превью в WebP 1200×900, 4:3                                                                                                         |
| Контейнеры  | **Docker multi-stage + nginx**, Compose prod/dev  | Прод — лёгкий nginx, dev — hot reload                                                                                                                  |
| Пакеты      | npm + `package-lock.json`                         | Воспроизводимость; локально `npm.cmd`                                                                                                                  |

**Почему не GSAP:** в стеке уже Motion; две анимационные библиотеки не нужны и увеличивают бандл. GSAP-скилл не ставим.

**Почему raw WebGL, а не React Three Fiber:** нужен только один анимированный фон, а не 3D-сцена с объектами. Fullscreen-шейдер на WebGL2 занимает единицы килобайт кода, не тянет Three.js (~150 КБ) и полностью контролируется по DPR/fps. R3F остаётся запасным вариантом, если пользователь захочет объёмные объекты и интерактивную сцену (см. развилку 18.1).

**Почему не Next.js:** лендингу не нужен сервер; Astro + nginx даёт более лёгкий и быстрый результат.

### 6.1. Навигация

- Fixed, высота 72 px, контейнер 1152 px.

## 8. Система портфолио

### 8.1. Схема данных

`src/data/projects.json` — массив объектов. Новые работы добавляются **в конец**. Порядок отображения совпадает с порядком в файле (см. 8.2 про `featured`).

| Поле          | Тип                                          | Обязательное | Правило                                                            |
| ------------- | -------------------------------------------- | ------------ | ------------------------------------------------------------------ |
| `id`          | string                                       | да           | slug латиницей, уникальный, например `landing-coffee-shop`         |
| `title`       | string                                       | да           | название работы                                                    |
| `category`    | `"landing" \| "bot" \| "layout" \| "script"` | да           | одна из четырёх категорий                                          |
| `client`      | string                                       | нет          | тип клиента/проекта, например «Кофейня»                            |
| `description` | string                                       | да           | 1–2 предложения о задаче и результате                              |
| `stack`       | string[]                                     | да           | технологии                                                         |
| `cover`       | string                                       | да           | `/portfolio/<id>.webp`                                             |
| `link`        | string                                       | нет          | демо или кейс                                                      |
| `date`        | string                                       | да           | `YYYY-MM`, например `2026-03`                                      |
| `featured`    | boolean                                      | да           | показывать в начале списка                                         |
| `example`     | boolean                                      | нет          | только у одного демо-проекта; удаляется при первой реальной работе |

Тип `Project` — в `src/types/project.ts`; валидация Zod — в `src/lib/projects.ts` и в `scripts/validate-projects.mjs` (проверка перед сборкой).

### 8.2. Порядок и `featured`

В ТЗ есть два требования, которые конфликтуют:

- «Порядок отображения совпадает с порядком в файле».
- `featured: true` — «показывать ли в начале списка».

**Решение по умолчанию:** стабильная сортировка: сначала `featured: true`, затем остальные; внутри каждой группы — порядок файла. Так `featured` имеет смысл, а новые работы не ломают порядок. Это фиксируется в `PORTFOLIO_GUIDE.md`. Если пользователь хочет строго файловый порядок, сортировка отключается одной строкой.

### 8.3. Компонент

- `src/components/portfolio/ProjectCard.tsx` — **единственный** компонент карточки, принимает только `project: Project`.
- Внутри: превью 4:3, бейдж категории, бейдж «Пример» при `example`, заголовок, клиент, описание, стек, дата, ссылка.
- Все размеры, радиусы, тени и hover-эффекты заданы в `ProjectCard` и его CSS-классах. Секция не переопределяет карточку.
- Секция `Portfolio.tsx`:
  - импортирует массив, валидирует, строит уникальные категории;
  - рендерит кнопки фильтра (Все + категории);
  - `map` по отфильтрованному массиву;
  - не содержит захардкоженных карточек;
  - показывает пустое состояние при пустом массиве.
- Фильтр: `aria-pressed`, `aria-live` с количеством, анимация layout через Motion.
- Если JS недоступен: показываются все карточки, фильтры скрыты (progressive enhancement).

### 8.4. Категории

Автоматически из данных; порядок — по первому появлению в файле. Подписи:

- `landing` → «Лендинги»
- `bot` → «Telegram-боты»
- `layout` → «Вёрстка»
- `script` → «Скрипты»

Если в данных появится неизвестная категория, кнопка создастся с сырым значением (и это будет ошибкой валидации, чтобы не проскочило незаметно).

### 8.5. Демо-проект

```json
{
  "id": "landing-coffee-shop",
  "title": "Кофейня «Зерно»",
  "category": "landing",
  "client": "Кофейня",
  "description": "Лендинг для локальной кофейни: меню, атмосфера и заявка на бронь столика.",
  "stack": ["Astro", "Tailwind CSS", "TypeScript"],
  "cover": "/portfolio/landing-coffee-shop.webp",
  "link": "",
  "date": "2026-03",
  "featured": false,
  "example": true
}
```

- На карточке — бейдж «Пример».
- В README — явное указание удалить запись при добавлении первой реальной работы.
- Превью: 1200×900 WebP, 4:3, генерируется из скрытой demo-страницы (реальный скриншот макета) или AI-визуала; без внешних лицензионных ассетов.

### 8.6. Изображения

- `public/portfolio/<id>.webp` (допускается AVIF).
- Ширина ≤1200 px, соотношение 4:3, качество 80–85.
- Имя файла = `id`.
- `scripts/prepare-cover.mjs` (sharp): принимает исходник и id, кропает по центру до 4:3, ресайзит до 1200×900, сохраняет WebP.
- `width`/`height` в `<img>` обязательны, `loading="lazy"`, `decoding="async"`.

### 8.7. Валидация

`scripts/validate-projects.mjs`:

- Zod-схема;
- уникальность `id`;
- допустимые категории;
- формат `date` `YYYY-MM`;
- наличие файла `cover` в `public`;
- `example: true` максимум у одной записи;
- отсутствие «битых» ссылок (если `link` задан — валидный URL).

Запускается в `npm run validate` и перед `npm run build` (prebuild).

### 8.8. Инструкция

`PORTFOLIO_GUIDE.md` в корне — ровно по ТЗ (8 шагов + схема + пример). README содержит абзац-процедуру, чтобы можно было сказать агенту: «добавь работу: …».

## 10. Анимации

| Эффект           | Где                      | Реализация                                                               | Reduced motion      |
| ---------------- | ------------------------ | ------------------------------------------------------------------------ | ------------------- |
| Появление hero   | Hero                     | Motion: opacity 0→1, y 24→0, blur 8→0, stagger 60 ms, 800 ms             | Мгновенно           |
| WebGL silk-фон   | Hero                     | GLSL fbm/domain warp, 60 fps desktop / 30 fps mobile, пауза вне вьюпорта | Статичный кадр      |
| Параллакс фона   | Hero                     | CSS-переменные от pointermove, max 8 px, RAF + `u_pointer` в шейдере     | Отключён            |
| Пульс свечения   | Знак в hero              | CSS keyframes 6 s ease-in-out                                            | Статично            |
| Пылинки          | Hero                     | CSS dots, drift 12–24 s                                                  | Скрыты              |
| Reveal секций    | Все                      | Motion `inView`, y 24, opacity, 600 ms, stagger 70 ms                    | Мгновенно           |
| Marquee          | Технологии               | CSS `translateX`, 40 s linear, duplicate track                           | Статичный flex-wrap |
| Hover карточек   | Услуги, портфолио, bento | border, translateY(-2…-4), spotlight, image scale 1.03, 200–300 ms       | Без transform       |
| Фильтр портфолио | Портфолио                | Motion layout + AnimatePresence, 300 ms                                  | Мгновенная смена    |
| Мобильное меню   | Header                   | Sheet: fade + slide, focus trap                                          | Мгновенно           |
| Кнопки           | Все                      | shine sweep, active scale 0.98, 160 ms                                   | Без sweep           |
| Lenis            | Вся страница             | lerp 0.1, якоря с offset 80                                              | Отключён            |

Правила:

- Анимируются только `transform` и `opacity`; не `top/left/width/height`.
- `will-change` — точечно и только на время анимации.
- Все анимации отключаются через `prefers-reduced-motion: reduce` и `useReducedMotion()`.
- Нет автопрокрутки, мерцания и мигания.

## 14. Производительность и Lighthouse

Бюджет:

- JS ≤120 КБ gzip (React + Motion + Lenis + islands).
- CSS ≤25 КБ gzip.
- Шрифт: 2 сабсета Manrope (кириллица + латиница), preload кириллицы.
- Hero: WebGL2 silk-шейдер (один quad, без Three.js) + статичный WebP-fallback; шейдер не блокирует первый рендер, запускается после `DOMContentLoaded`/`requestIdleCallback`.
- Hero fallback-кадр: AVIF/WebP, `srcset` 1280/1920/2560; при reduced motion или отсутствии WebGL — только он.
- Шейдер: DPR ≤1.5 desktop / ≤1 mobile, 60/30 fps, пауза при `visibilitychange` и вне вьюпорта, контекст теряется — показываем fallback.
- Превью портфолио: WebP 1200×900, `loading="lazy"`.
- Без внешних CDN, аналитики и тяжёлых библиотек.
- Изображения с явными `width`/`height`, чтобы CLS = 0.
- Reveal не скрывает контент от поисковиков (SSR HTML + opacity), но при JS-сбое текст остаётся видимым (класс `js` на `<html>`).
- LCP — текст H1, не картинка; hero-фон не блокирует рендер.
- Lighthouse mobile: Performance ≥90, Accessibility ≥95, Best Practices ≥95, SEO ≥100. Desktop ≥95 по performance.
- Проверка на 320/390/768/1024/1440/1920, медленный 4G, reduced motion.

## 18. Развилки и выбранные варианты

### 18.1. Hero: живой фон

**Вариант A:** статичный 3D-рендер волн (AVIF/WebP) + CSS-свечение — самый лёгкий, но без анимации.
**Вариант B (выбран):** собственный WebGL2 silk-шейдер (один fullscreen quad, без Three.js/R3F) + статичный fallback. Живые монохромные волны, реакция на курсор, низкий вес, контроль DPR/fps.
**Вариант C:** R3F/Three.js сцена с объёмными объектами — дороже по JS и сложнее; оставляем на будущее.
**Решение:** B. Референсы — Silk shader (MrKyzen) и Silky Moving Background (Adam Guerreiro) на 21st.dev; код пишем свой.

### 18.2. `featured` и порядок

**Выбрано:** стабильная сортировка featured-first, внутри — порядок файла. Иначе поле `featured` не имеет смысла. Альтернатива — строго файловый порядок, `featured` только как бейдж.

### 18.3. Заглушки Telegram/VK

**Выбрано:** кнопки выглядят активными, по клику показывают «Ссылка скоро появится» через aria-live. Не ведут на `#` и не выдумывают адреса. Альтернатива — disabled-кнопки; выглядит менее живо.

### 18.4. Шрифт

**Выбрано:** Manrope Variable (OFL, кириллица). Satoshi/General Sans ближе к референсу, но без надёжной кириллицы. Если пользователь предоставит лицензионный кириллический аналог — заменим.

### 18.5. Демо-превью

**Выбрано:** скриншот скрытой demo-страницы в стиле проекта (1200×900), а не AI-картинка. Даёт реалистичный макет и полный контроль. AI-генерация — запасной вариант.

### 18.6. Портфолио: React или Astro-карточки

**Выбрано:** React-остров для секции (фильтр + Motion layout), `ProjectCard` — React-компонент. Astro отрендерит HTML на сервере, SEO не страдает. Альтернатива — Astro-карточки + vanilla-фильтр, меньше JS, но меньше анимационных возможностей.

### 18.7. Нижняя часть референса

Обрезана. Контакты и футер проектируются в том же языке: центрированный CTA, свечение, тонкая рамка, белая pill, минимум ссылок. Это допущение, а не попытка угадать невидимый блок.

`gh` отсутствует. Автоматическое создание репозитория и PR невозможно. Публикация — GitHub Desktop; при установке `gh` команды готовы.
